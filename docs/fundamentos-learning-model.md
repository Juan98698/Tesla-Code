# Fundamentos JavaScript: proyecto y retos encadenados

Decisión del usuario, 16 de noviembre de 2026. Esta dirección sustituye el patrón
de actividades aisladas para toda la ruta de Fundamentos con JavaScript.

## Requisitos del recorrido

La persona empieza sin experiencia de programación. Todo término, símbolo,
operación y herramienta se explica con un ejemplo antes de pedir su aplicación.
La revisión incluye enunciados, código inicial, pistas, soluciones, preguntas y
datos de prueba. Cada nueva capacidad reutiliza conocimientos ya introducidos.

Cada unidad integra cuatro pasos:

1. **Entender:** interpretar el problema y la versión anterior, predecir y elegir
   un plan. Se conserva el análisis de decisiones y una bitácora personal.
2. **Implementar:** construir el primer incremento con apoyo y comprobarlo.
3. **Reescribir y comprobar:** recuperar el código aprobado, cambiarlo según el
   nuevo requisito y contrastar resultados y casos. Al principio no se necesitan
   métodos avanzados: reescribir puede significar ordenar instrucciones o nombrar
   un dato.
4. **Integrar y depurar:** reutilizar el incremento y resolver una variante o fallo
   antes de entregar la siguiente versión.

Las pistas son opcionales y progresivas. Los casos comprueban el contrato
observable. Un análisis de decisiones comprueba reconocimiento y predicción,
no autoría de una explicación. La bitácora se conserva y ofrece criterios de
autorrevisión; no se califica su semántica buscando palabras clave.

## Producto y entregas

**Mi plan de práctica** empieza como un saludo y se convierte progresivamente en
un planificador: información, datos, cálculos, entradas, decisiones, sesiones,
funciones, colecciones, módulos, interfaz y comunicación asíncrona.

El código aprobado se conserva por reto y alimenta el siguiente. Los borradores
siguen siendo editables e independientes; un intento fallido no reemplaza una
versión aprobada. El estudiante puede volver a una versión y exportar su trabajo.
La copia de progreso conserva también las entregas y la bitácora. Recuperar una
versión no concede XP ni completa el nuevo contrato.

## Implementación incremental

El primer lote migra las ocho lecciones del módulo inicial al mismo proyecto y
al ciclo de cuatro pasos. Los otros diez temas publicados conservan su material
y requieren migración editorial; no basta añadirles etiquetas. Los doce bloques
posteriores continúan en preparación. El objetivo es aplicar el modelo a todos,
con revisión y entrega de módulos completos, sin simular contenido avanzado.

| Siguiente tramo                | Conocimientos que debe preparar                                                     | Incremento del proyecto             |
| ------------------------------ | ----------------------------------------------------------------------------------- | ----------------------------------- |
| Tipos y decisiones             | Tipos, comparación, booleanos, ramas y validación                                   | Admitir datos y recomendar un plan  |
| Ciclos y funciones             | Traza, parada, acumulación, parámetros y retorno                                    | Procesar sesiones y separar reglas  |
| Listas y texto                 | Índices, recorridos, mutabilidad y contratos                                        | Conservar y resumir sesiones        |
| Funciones como valores y datos | Callbacks, objetos, referencias, métodos y diccionarios                             | Consultar y agrupar planes          |
| Resolver y medir               | Casos, invariantes, estrategias, recursión y coste                                  | Elegir y justificar soluciones      |
| Lenguaje y herramientas        | Alcance, errores, módulos, archivos, terminal y depuración                          | Organizar el producto y sus pruebas |
| Web y asincronía               | HTML/CSS antes de DOM; eventos antes de persistencia; promesas antes de await/fetch | Interfaz y datos externos           |
| Calidad y proyecto final       | Accesibilidad, errores, pruebas y entrega reproducible                              | Aplicación integrada comprobable    |

## Condiciones de cierre de un módulo

- Cada construcción usada tiene introducción, ejemplo y práctica identificables.
- Las entregas se reutilizan de verdad y se pueden recuperar; el código del
  estudiante no se reemplaza silenciosamente por la solución del autor.
- Se prueban soluciones equivalentes y errores frecuentes, incluyendo extremos,
  longitudes, posiciones y orden cuando importan al problema.
- Se distingue práctica guiada de transferencia a una situación nueva.
- Se revisan datos y enunciados para evitar aprobaciones falsas y rechazos de
  respuestas equivalentes.
- Se verifican progreso antiguo, teclado, móvil, borradores y respaldo.
- Revisión docente independiente y piloto con principiantes siguen pendientes
  hasta que se realicen. Las pruebas automáticas no sustituyen esa evidencia.
