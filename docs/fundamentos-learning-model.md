# Fundamentos JavaScript: proyecto y retos encadenados

Decisión del usuario, 16 de noviembre de 2026. Esta dirección sustituye el patrón
de actividades aisladas para toda la ruta de Fundamentos con JavaScript.

## Requisitos del recorrido

La persona empieza sin experiencia de programación. Todo término, símbolo,
operación y herramienta se explica con un ejemplo antes de pedir su aplicación.
La revisión incluye enunciados, código inicial, pistas, soluciones, preguntas y
datos de prueba. Cada nueva capacidad reutiliza conocimientos ya introducidos.

Cada unidad integra cuatro pasos:

1. **Entender:** interpretar el problema y la versión anterior, predecir y elegir
   un plan. Se conserva el análisis de decisiones y una bitácora personal.
2. **Implementar:** construir el primer incremento con apoyo y comprobarlo.
3. **Reescribir y comprobar:** recuperar el código aprobado, cambiarlo según el
   nuevo requisito y contrastar resultados y casos. Al principio no se necesitan
   métodos avanzados: reescribir puede significar ordenar instrucciones o nombrar
   un dato.
4. **Integrar y depurar:** reutilizar el incremento y resolver una variante o fallo
   antes de entregar la siguiente versión.

Las pistas son opcionales y progresivas. Los casos comprueban el contrato
observable. Un análisis de decisiones comprueba reconocimiento y predicción,
no autoría de una explicación. La bitácora se conserva y ofrece criterios de
autorrevisión; no se califica su semántica buscando palabras clave.

## Producto y entregas

**Mi plan de práctica** empieza como un saludo y se convierte progresivamente en
un planificador: información, datos, cálculos, entradas, decisiones, sesiones,
funciones, colecciones, módulos, interfaz y comunicación asíncrona.

El código aprobado se conserva por reto y alimenta el siguiente. Los borradores
siguen siendo editables e independientes; un intento fallido no reemplaza una
versión aprobada. El estudiante puede volver a una versión y exportar su trabajo.
La copia de progreso conserva también las entregas y la bitácora. Recuperar una
versión no concede XP ni completa el nuevo contrato.

## Implementación incremental

Las treinta lecciones publicadas construyen el mismo proyecto con las cuatro
etapas. El primer módulo conserva ocho lecciones. Los cuatro bloques siguientes
tienen cuatro lecciones cada uno: valores y operaciones, decisiones y validación,
repeticiones y funciones. Listas tiene seis lecciones. La distribución separa
habilidades que antes se exigían simultáneamente. Conserva los tres repasos
anteriores y sus IDs; se añaden cuatro transferencias obligatorias después de
integrar. Los doce bloques posteriores continúan en
preparación; la migración de lo publicado no significa que estén desarrollados.

| Siguiente tramo                | Conocimientos que debe preparar                                                     | Incremento del proyecto             |
| ------------------------------ | ----------------------------------------------------------------------------------- | ----------------------------------- |
| Tipos y decisiones             | Tipos, comparación, booleanos, ramas y validación                                   | Admitir datos y recomendar un plan  |
| Ciclos y funciones             | Traza, parada, acumulación, parámetros y retorno                                    | Procesar sesiones y separar reglas  |
| Listas y análisis              | Índices, recorridos, mutabilidad y contratos                                        | Conservar y resumir sesiones        |
| Funciones como valores y datos | Callbacks, objetos, referencias, métodos y diccionarios                             | Consultar y agrupar planes          |
| Resolver y medir               | Casos, invariantes, estrategias, recursión y coste                                  | Elegir y justificar soluciones      |
| Lenguaje y herramientas        | Alcance, errores, módulos, archivos, terminal y depuración                          | Organizar el producto y sus pruebas |
| Web y asincronía               | HTML/CSS antes de DOM; eventos antes de persistencia; promesas antes de await/fetch | Interfaz y datos externos           |
| Calidad y proyecto final       | Accesibilidad, errores, pruebas y entrega reproducible                              | Aplicación integrada comprobable    |

## Condiciones de cierre de un módulo

- Cada construcción usada tiene introducción, ejemplo y práctica identificables.
- Las entregas se reutilizan de verdad y se pueden recuperar; el código del
  estudiante no se reemplaza silenciosamente por la solución del autor.
- Se prueban soluciones equivalentes y errores frecuentes, incluyendo extremos,
  longitudes, posiciones y orden cuando importan al problema.
- Se distingue práctica guiada de transferencia a una situación nueva.
- Se revisan datos y enunciados para evitar aprobaciones falsas y rechazos de
  respuestas equivalentes.
- Se verifican progreso antiguo, teclado, móvil, borradores y respaldo.
- Revisión docente independiente y piloto con principiantes siguen pendientes
  hasta que se realicen. Las pruebas automáticas no sustituyen esa evidencia.

## Contrato de evidencias de las treinta publicaciones

Las cuatro etapas requieren entregar una explicación. Las tres de código exigen
además una predicción estructurada; integración añade un diagnóstico y la ejecución
de una incidencia defectuosa independiente del borrador recuperado. Se conservan
salida/error observado, respuestas, código comprobado y resultados de comparación.
La bitácora pide predicción, traza y justificación; en depuración pide síntoma,
entrada, hipótesis, prueba, causa y corrección. Entregar escritura libre no implica
que su razonamiento haya recibido aprobación humana: queda pendiente de revisión.

Cada incremento declara las capacidades conservadas y el motivo de su cambio.
El reporte mantiene saludo, título y estado; luego añade sesión/duración/días,
meta/recordatorio, referencia de duración, total, nombre y comparación ampliada.
La confirmación de 30 minutos en `let` continúa como dato actual al calcular 150
minutos; 20 se mantiene como referencia histórica. Ninguna reescritura cambia ese
contrato por accidente.

La reescritura ejecuta la versión anterior real del estudiante y compara las
salidas completas para los mismos casos comunes. Las variantes nuevas se verifican
por separado: la versión anterior no recibe requisitos aún no introducidos.
Comentarios, declaraciones y tipos se contrastan cuando forman parte de la
habilidad anunciada. Las variantes de configuración cambian solo inicializadores
analizados sintácticamente, dentro del ejecutor aislado; no se ejecuta código del
estudiante en la página anfitriona. No se califican explicaciones por palabras clave.

Una evaluación nueva no se completa únicamente con quiz y marcas históricas de
práctica: necesita la evidencia de cada etapa. Se conservan las lecciones ya
completadas, sus IDs y XP. Los borradores fallidos no reemplazan entregas aprobadas.
Cambiar la explicación obliga a registrarla de nuevo; editar código exige comprobar
esa nueva versión. El respaldo incluye los registros de evidencia.

## Continuidad posterior a la tarjeta inicial

Los tipos y comparaciones amplían el reporte sin cambiarlo por accidente. La
clasificación respeta los umbrales inclusivos de 30 y 60. La validación separa
los datos válidos de un rechazo explícito: las entradas inválidas no producen
reportes parciales; cero sigue siendo válido. Después se reciben días entre 0 y
7 y se enumeran las sesiones, conservando los cinco días originales como caso.

Los ciclos acumulan minutos programados y cuentan días pares. La introducción
de funciones mantiene el programa completo, pero también prueba retornos con
argumentos distintos de los leídos por el reporte. Las reescrituras comparan
ambas observaciones: igualdad de impresión no sustituye igualdad de retorno.
calcularTotal admite hasta 125 minutos por día para proyectar cinco adicionales
a una base válida máxima de 120; esa ampliación no cambia la validación de entrada.

Las listas se construyen con la cantidad anunciada y entradas de cada sesión,
antes de presentar resultados. Las funciones reciben listas independientes y
deben conservarlas. La entrega final reúne suma, conteo inclusivo y máximo,
define la vacía y comprueba extremos, repetidos y máximos en ambas puntas. El
máximo también se contrasta con negativos en su contrato independiente; los
minutos reales introducidos siguen siendo no negativos.

Los cuestionarios y las tres transferencias anteriores mantienen sus identificadores
y problemas distintos. Se conservan logros previos. La revisión docente
independiente y el piloto con principiantes continúan pendientes.

La [revisión de granularidad y claridad](revision-granularidad-fundamentos.md)
registra las separaciones y su justificación. Decisiones introduce dos caminos,
después categorías y reglas booleanas, y finalmente valida texto y números. Las
reglas preparadas se reutilizan en validación; los valores iniciales alternativos
y los datos esperados y observados son visibles al comprobar. Repeticiones separa
while, for equivalente, acumulación y conteo condicional. Funciones separa retorno,
composición, extracción de reglas y retornos tempranos. Listas separa construcción,
suma, resumen y máximo; el par construido se reutiliza para devolver el resumen.

Las pistas orientan desde el análisis hasta una traza de la habilidad concreta.
Una respuesta incorrecta ofrece orientación local; una coincidencia técnica no
aprueba la calidad del razonamiento escrito. Los errores de tipo muestran el valor
y el tipo observados, aunque la salida impresa sea idéntica a la esperada.

## Distribución de Valores, tipos y operaciones

El bloque se desarrolla en cuatro lecciones secuenciales, con una entrega por
lección y cuatro etapas por entrega:

1. Tipos y representación (`js-tipos-y-calculos`, ID conservado): valores de texto,
   número, booleanos, ausencia y consulta con typeof. El proyecto solo añade el
   tipo de los minutos; no exige todavía resta, división ni resto.
2. Operaciones y unidades (`js-operaciones-y-unidades`): resta, división, resto,
   agrupación, unidades y límites de Number. Añade horas, sobrante y margen diario.
3. Comparaciones (`js-comparaciones`, ID conservado): igualdad estricta, diferencia
   y fronteras inclusivas con cantidades que ya se saben interpretar.
4. Integración (`js-integrar-valores`): otro pedido, datos nuevos, equivalencia
   entre dos cuentas de una ampliación diaria y pruebas elegidas por el error que
   revelan. Conserva el reporte y prepara el uso de booleanos en Decisiones.

Se conservan IDs, completados y XP existentes; las nuevas lecciones no se acreditan
automáticamente. Los prerrequisitos y las fuentes de entregas reflejan el nuevo
orden. Las pruebas estructurales contrastan que los retos de tipos no exijan las
operaciones ni el control de flujo de lecciones posteriores. El criterio de cierre
incluye revisar la granularidad y la continuidad teórica, además de ejecutar casos.

## Dimensionar por el alcance del tema

El usuario exige entregar coherencia antes del piloto: el contenido y la práctica
determinan la cantidad de lecciones, sin una cuota común ni relleno. La
[revisión de alcance y carga](fundamentos-alcance-y-carga.md) registra las
habilidades, sus usos y las introducciones pendientes del lenguaje actual. Listas
separa construcción, lectura validada, suma, conteo, resumen y máximo. En valores,
decisiones, ciclos y funciones se añaden transferencias que comprueban límites,
aportes variables y composición en problemas distintos. Cada etapa conserva el
trabajo anterior; las APIs y herramientas nuevas se introducen antes de usarlas.
